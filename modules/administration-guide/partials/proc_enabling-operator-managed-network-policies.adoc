= Enable Operator-managed network policies

[role="_abstract"]
Enable Operator-managed network policies to restrict ingress traffic to the {prod-short} components, such as the gateway, server, dashboard, and registries.
The {prod-short} Operator creates and manages the NetworkPolicy resources automatically.
This feature is controlled by the `spec.networking.networkPolicy.enabled` CheCluster field and is disabled by default.

The NetworkPolicies are created in the {prod-short} {orch-namespace} and apply only to the Pods labeled with `app.kubernetes.io/part-of=che.eclipse.org`.
When this field is set to `false`, the NetworkPolicies previously created by the Operator are removed.

.Prerequisites
* An active `{orch-cli}` session with administrative permissions to the destination {orch-name} cluster. See {orch-cli-link}.

.Procedure
. Enable Operator-managed network policies:
+
[source,shell,subs="+quotes,+attributes"]
----
{orch-cli} patch checluster/{prod-checluster} \
  --namespace {prod-namespace} \
  --type merge \
  --patch '{"spec":{"networking":{"networkPolicy":{"enabled":true}}}}'
----

. Because workspace isolation inherits this setting, set `spec.devEnvironments.networking.networkPolicy.enabled` explicitly to `false` if you want to isolate only the {prod-short} components:
+
[source,shell,subs="+quotes,+attributes"]
----
{orch-cli} patch checluster/{prod-checluster} \
  --namespace {prod-namespace} \
  --type merge \
  --patch '{"spec":{"devEnvironments":{"networking":{"networkPolicy":{"enabled":false}}}}}'
----

.Verification
* Verify that the NetworkPolicy resources are created in the {prod-short} {orch-namespace}:
+
[source,shell,subs="+quotes,+attributes"]
----
{orch-cli} get networkpolicies -n {prod-namespace}
----
+
* If network isolation for workspaces is enabled, start a workspace and verify that a NetworkPolicy resource is created for it in the user {orch-namespace}:
+
[source,shell,subs="+quotes,+attributes"]
----
{orch-cli} get networkpolicies -n __<user_namespace>__
----
