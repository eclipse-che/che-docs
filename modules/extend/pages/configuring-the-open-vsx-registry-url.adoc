= Use an alternative extension registry

[role="_abstract"]
Use an alternative Open VSX registry instance instead of the managed registry that the Operator deploys by default. Select the public open-vsx.org registry for internet-connected environments, or a standalone on-premises instance for full control over available extensions.

If the managed Open VSX registry does not meet your requirements, you can select one of the following instances:

* The Open VSX registry instance at `pass:c,a,q[https://open-vsx.org]` that requires access to the internet.

* A standalone Open VSX registry instance that is deployed on a network accessible from {prod-short} workspace pods.

.Prerequisites

* You have administrator access to the cluster where {prod-short} is deployed.
* You have an active `{orch-cli}` session with administrative permissions. See {orch-cli-link}.

.Procedure

. Edit the `CheCluster` custom resource to update the `openVSXURL` value:
+
[source,yaml,subs="+quotes"]
----
spec:
  components:
    pluginRegistry:
      openVSXURL: "__<url_of_an_open_vsx_registry_instance>__"
----
+
where `__<url_of_an_open_vsx_registry_instance>__` is the URL of the public or standalone Open VSX registry instance. For example: `pass:c,a,q[https://open-vsx.org]`. The URL must be accessible from within your organization's cluster and not blocked by a proxy.
+
A non-empty `openVSXURL` value takes effect on its own. You do not have to disable the managed Open VSX registry to use a public or standalone instance. The managed registry continues to run and consume cluster resources until you disable it. To remove it, see xref:enabling-the-managed-open-vsx-registry.adoc#disabling-the-managed-open-vsx-registry[Disable the managed Open VSX registry].
+
[IMPORTANT]
====
An empty value and an unset field are not the same. An empty value selects the embedded registry. An unset field selects the default registry.
====

. Optional: To select the deprecated embedded Open VSX registry instance in the `plugin-registry` pod, set `openVSXURL` to an empty string and disable the Open VSX operand:
+
[source,yaml,subs="+quotes"]
----
spec:
  components:
    openVSXRegistry:
      enable: false
    pluginRegistry:
      openVSXURL: ""
----
+
The embedded registry requires both fields. {prod-short} does not deploy the `plugin-registry` pod while the managed Open VSX registry is enabled. You can customize the list of included extensions. See xref:extensions-for-microsoft-visual-studio-code-open-source.adoc[].
+
[NOTE]
====
To ensure the stability and performance of the community-supported Open VSX Registry, API usage is organized into defined tiers. The Eclipse Foundation implements these limits to protect infrastructure from high-frequency automated traffic and to provide consistent service quality for all users. For more information, see link:https://github.com/EclipseFdn/open-vsx.org/wiki/rate-limiting[Rate Limits and Usage Tiers] and the link:https://github.com/EclipseFdn/open-vsx.org/wiki[open-vsx.org wiki].
====
+
[IMPORTANT]
====
Using link:https://open-vsx.org[https://open-vsx.org] is not recommended in an air-gapped environment, isolated from the internet. To reduce the risk of malware infections and unauthorized access to your code, use the embedded or self-hosted Open VSX registry with a curated set of extensions.
====
+
[WARNING]
====
Due to the dedicated Microsoft link:https://cdn.vsassets.io/v/M190_20210811.1/_content/Microsoft-Visual-Studio-Marketplace-Terms-of-Use.pdf[Terms of Use], link:https://marketplace.visualstudio.com/vscode[Visual Studio Code Marketplace] is not supported by {prod}.
====

.Verification

* Open a workspace and verify that extensions are available from the selected registry instance in the *Extensions* view.

* If you selected the embedded registry, confirm that the `plugin-registry` pod is running:
+
[source,shell,subs="+quotes,+attributes,+macros"]
----
{orch-cli} get pods --namespace {prod-namespace} -l app.kubernetes.io/component=plugin-registry
----
